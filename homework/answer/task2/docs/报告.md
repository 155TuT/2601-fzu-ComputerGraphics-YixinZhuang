## 一、概述

## 二、贝塞尔曲线和曲面

### 1. 基于 1D de Casteljau 绘制贝塞尔曲线

给定控制点 p₀ 到 pₙ 和参数 t，先对每对相邻点作线性插值：qᵢ = (1−t)pᵢ + tpᵢ₊₁。每计算一层，点的数量减少一个；不断重复，最后一个点就是曲线在 t 处的位置。这个过程保留了控制多边形到曲线上一点之间的几何联系，也方便显示中间层。

`BezierCurve::evaluateStep` 负责计算一层插值，参数 t 取自曲线对象。界面的 E 键逐层调用它，C 键显示完整曲线。将 t 取为 0 或 1 时，曲线分别经过首尾控制点；连续改变 t，最终点沿曲线移动。

<!-- images: bezier-curve.png | bezier-curve2.png -->

图 2.1 左为 `curve1.bzc` 的三次曲线，右为 `curve2.bzc` 的四次曲线。白色为原始控制点，蓝色为中间插值点，红色为当前求值点，绿色为完整曲线。

两条曲线都经过首尾控制点。图中的中间点逐层靠近曲线上的求值点，展示了同一套递推对不同阶次的适用性。

### 2. 基于 1D de Casteljau 绘制贝塞尔曲面

贝塞尔曲面的求值分两次进行。先对控制网格的每一行调用一维求值，以 u 得到一个中间点；再把这些点作为一条曲线的控制点，以 v 求值，得到曲面上的点 P(u,v)。这样可以复用同一套线性插值逻辑。

`BezierPatch::evaluateStep` 计算一层三维插值，`evaluate1D` 逐层收敛到一个点，`evaluate` 组织行方向和列方向的两次求值。编辑器随后在参数域中采样，将这些点连接成三角网格。控制点决定连续曲面，显示网格的采样密度决定屏幕上能呈现多少细节。

## 三、三角网格和半边数据结构

### 3. 基于面积加权的顶点法线计算

顶点法线来自相邻三角面的共同贡献。对面上的两条边作叉积，其方向是面法线，长度等于三角形面积的两倍。直接累加这些叉积，最后统一归一化，就得到面积加权顶点法线。

`Vertex::normal` 从顶点的一条出射半边开始，通过 `twin()->next()` 遍历相邻面。边界环作为拓扑记录处理，有效三角面参与法线累加。叉积顺序遵循半边绕面的方向，使相邻面的法向保持一致。

平面着色在一个三角形内使用同一法线，面与面之间的明暗会跳变。Phong 着色插值顶点法线，使光照沿表面连续变化。两种结果的几何顶点和三角形数量相同，变化来自着色所用的法线。

图 3.1 `dae/teapot.dae` 的法线对比。左为面法线，右为面积加权顶点法线；两图使用相同 Blinn–Phong 着色器、视角与光照。

### 4. 边翻转

设两个相邻三角形为 (a,b,c) 与 (c,b,d)，共享边为 bc。翻转后用 ad 替换 bc，两个面成为 (a,b,d) 与 (c,a,d)。操作只改变局部连接关系，顶点位置和网格元素总数保持一致。

实现先记录局部半边、顶点、边和面，再成组更新半边的 `next`、`twin`、`vertex`、`edge`、`face`，最后更新顶点、边和面的代表半边。先保存关系再改写，可以避免遍历过程中丢失原有邻接信息。边界边只有一个相邻三角面，保持原状。

### 5. 边分割

分割内部边 bc 时，在中点 m = (b+c)/2 插入一个顶点，并把 m 与两侧的对角顶点连接。原来的两个三角面变为四个，顶点数增加 1，边数增加 3，面数增加 2。

`HalfedgeMesh::splitEdge` 创建新增元素后，按照四个三角形各自的环重新连接半边，并修正外侧半边的对应关系。返回的新顶点由后续 Loop 细分继续使用。与翻转相同，单次分割的核心操作范围是被选边及其相邻三角面。

### 6. 利用 Loop Subdivision 进行网格上采样

一次 Loop 细分包含拓扑细分和顶点位置更新。实现先保存旧顶点与旧边的状态，使用原网格位置计算新坐标；然后分割每条原边，将每个三角形细分为四个；再翻转连接一个新顶点与一个旧顶点的合适新边；最后统一写回坐标。

内部边的新顶点采用 P = 3/8(A+B) + 1/8(C+D)，A、B 是边的端点，C、D 是两侧对角顶点。旧顶点采用 P′ = (1−nu)P + u∑Pᵢ，其中 n 为顶点度数；n=3 时 u=3/16，其余情况 u=3/(8n)。统一计算后再更新，保证每个顶点都使用同一轮的邻居位置。

边界新顶点取原边中点；旧边界顶点使用 P′ = 3/4P + 1/8(P左+P右)，其中 P左、P右为两个边界邻点。这组权重使边界在细分时形成平滑曲线。

### 立方体预处理与对称性

立方体每个四边形面经过三角化后，会引入一条对角线。不同角点连接的对角线数量可能不同，导致顶点度数和一环邻居分布出现差异。Loop 的位置更新依赖这些连接，因而规则立方体也可能在多次细分后出现轻微不对称。

本次预处理找出立方体六个面上的共面对角线，对每条对角线作中点分割。每个正方形面得到一个中心点，并连接四个角点，形成对称的四三角形结构。此时各角点的一环分布相互对应，后续细分也能保持这种对称关系。

图 3.8 左为原始三角化立方体，右为分割六条面对角线后的立方体。

<!-- images: cube-loop3.png | cube-symmetric-loop3.png -->

图 3.9 两种初始连接分别经过三次 Loop 细分。右图的外轮廓更对称，网格沿各面的分布也更均衡。

### 尖角与边界的变化

Loop 的加权平均会把顶点向邻域内部移动，尖角逐渐圆化，整体形状也会收缩。对尖角附近的边预先分割，可以增加局部采样点，缩小后续平均的影响范围，保留更多局部形状。若需要长期保持明确的折痕，可进一步引入折痕标记与专门的细分权重。

### 7. 自建人形网格与环境贴图

本次采用程序化建模。`docs/models/humanoid.json` 保存头、躯干、手臂和双腿的整数盒体参数；`scripts/build_humanoid.py` 取这些盒体的并集，再挖出眼窝，得到抬手的人形。模型由 300 个体素组成，提取 530 个外露四边形，合并共享角点，并在每个四边形中心加入一点，将它分为四个三角形。输出同时保存为可编辑的 OBJ 和可由程序加载的 `code/dae/custom/humanoid.dae`。

提取表面时，共享体素之间的内部面会被消去。生成结果只有一个连通分量，边界边数量为 0，欧拉示性数为 2；每条边连接两个朝向相反的面，每个顶点的一环形成单一闭环。这些检查保证人形的各部分连接成完整表面，能够继续进行半边操作。

## 四、实践与思考

半边操作最关键的检查对象是连接关系。画面能显示一个模型，只能说明当前绘制路径走通；连续进行分割、翻转和细分，才会进一步暴露环断裂、代表半边失效或旧新元素标记错误等问题。因此，几何结果与拓扑检查需要同时进行。

本次补充了边界构建中的代表半边设置。教师框架创建边界面时遗漏这条引用，会影响后续边界遍历和网格复制；补齐后，开放方形网格可以连续分割与细分。贝塞尔茶壶沿用教师框架的逐片加入与顶点合并流程，每加入一片后更新累计网格的共享顶点。

CTest 的五组验证全部通过。基础算法包含 4452 项检查；真实立方体、茶壶与开放方形场景分别完成 11527、1453297 和 5952 项检查，人形场景完成 1251031 项检查，覆盖连续操作后的半边连接与细分结果。两轮细分后，立方体的顶点、边、面数量为 98、288、192，茶壶为 19712、59136、39424，开放方形为 25、56、32。

运行验证把 PATH 限制为 Windows 系统目录，使用 `bin` 中的程序和运行时 DLL，分别导出曲线、贝塞尔茶壶和预处理立方体的图像，三组均成功结束。完整记录见 `verification/algorithm-tests.log` 与 `verification/runtime-smoke.json`。

曲线和曲面的求值便于用已知端点、中点及平面控制网格核对；网格操作则需要检查半边孪生关系、面环、顶点环和元素数量。将这些检查放在独立程序中，可以在修改算法后快速定位问题，再回到图形界面观察最终形状。
